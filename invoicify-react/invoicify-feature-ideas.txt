   HSN / SAC CODE — details (un kelvikku badil)
==================================================================
 Q: HSN type pannuma illa taana varuma?
   -> Item-la ORE THADAVA HSN type panni save.
      Invoice-la taana column-a varum. (Zoho maadhiri)
   -> Auto-select mudiyaathu: ore product rendu HSN-la varalaam,
      entha code sari-nu vyapari than decide pannanum.
      Software thappa select panna GST rate thappaagum.

 Q: HSN only GST-registered person-ku matuma?
   -> Aama, mostly. GST invoice podravanga than HSN podanum.
   -> Turnover-ku eaethapadi digit maarum:
        Rs 1.5 - 5 crore  -> 4 digit HSN (B2B mandatory)
        Rs 5 crore mela    -> 6 digit HSN (ellaa invoice)
        B2C (Rs 5cr keezha) -> optional
   -> Register pannaathavanga (unregistered/composition) ku
      strict-a thevai illa.

 DESIGN: HSN-a OPTIONAL field-a aakkanum.
   - GST person podanum, matravanga vittudalaam.
   - Force panna koodaathu.
   - Item-la HSN + tax rate save -> invoice-la auto.

==================================================================
   CRASH REPORTS — feature idea (attempted, reverted, not built)
==================================================================
Part of Settings -> Privacy & Security. Category: Privacy (data
sharing), not Security.

Idea: integrate Sentry (free tier) for crash/error reporting —
backend (@sentry/node) + frontend (@sentry/react). Settings would
have an On/Off toggle so the user can opt out of sending crash data
from their device.

Was fully built once (working code), then reverted at user's request
— setup process (2 separate Sentry projects/DSNs, env vars on both
Render + Vercel, npm installs) felt like too much for what it's
worth right now. No code currently in the project for this.

If revisited later, rough shape:
  - backend: instrument.js (Sentry.init, imported FIRST before
    anything else) + Sentry.setupExpressErrorHandler(app) after
    routes, before the app's own error handler. Needs SENTRY_DSN env
    var (Node.js project on sentry.io).
  - frontend: Sentry.init() in main.jsx before mounting React, wrap
    App in Sentry.ErrorBoundary with a friendly fallback UI instead
    of a blank white screen on crash. Needs VITE_SENTRY_DSN env var
    (separate React project on sentry.io) + a beforeSend() hook that
    checks a localStorage on/off flag so the Settings toggle works
    live without needing an app restart.
  - Settings -> Privacy & Security: simple On/Off segment control,
    same pattern as the App Lock toggle.
